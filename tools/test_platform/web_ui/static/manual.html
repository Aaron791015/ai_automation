你做判斷，它負責記得

測試助手把工作區裡散落的東西——測試案例、Bug 單、待辦、執行紀錄、規格文件—— 收成一份查得到的清單。你按一個鈕，它就開一個已經知道前因後果的 Claude 去做事；做完的東西自動存回檔案，你只要在畫面上看結果。

本機服務 · http://127.0.0.1:5300 · 每個人跑自己的一份，用自己的 Claude 帳號
先想知道「整套東西怎麼運作」？那一份是 AI 自動化測試框架 · 總覽 —— 四層架構、一件事從頭跑到尾的七站、人與 AI 的分界。 本手冊講的是操作：每一頁、每一顆按鈕、按下去會發生什麼。
本手冊的每一張圖都是真的跑出來的。 從一份全新匯出的範本開始：接上一個產品 → 寫案例 → 跑測試（含真的失敗那一輪） → 起任務 → 問對話 → 開單 → 回填 JIRA。畫面上的數字都是那一輪的實際結果，不是示意圖。

01這是什麼

先講它不做什麼，比較不會用錯。

它擅長
記得
哪張單還沒開、哪份交接檔落後了、上次跑失敗的是哪幾條。這些單一次對話看不到。
它擅長
開頭幫你講清楚
按鈕 → 填幾格 → 開一個已經載好規範、已經知道產品狀況的 Claude。省掉每次重講一遍。
它不做
代替你判斷
是規格還是缺陷、樣本夠不夠、這批資料能不能刪——這些還是你的事。
★ 它是一個範本，不是成品。 你手上這一份的流程 —— 有哪些任務按鈕、有哪些工具、產品柱長什麼樣 —— 只是一個能跑起來的開頭；每個團隊的測試流程本來就不一樣，本來就該改。 畫面上的東西幾乎都是宣告出來的，不是寫死在平台裡： 一支工具是一份 registry/<id>.tool.json、 一顆任務按鈕是一份 tasks/*.json、 一個產品是 config/products.json 的一列。 改這些檔就會改變畫面與流程，不必動平台程式—— 用不到的刪掉、缺的自己加、整條動線換成你們現在的做法都可以。 做法見 接新工具與新產品。

三件事它刻意不做

不做為什麼
不寫 JIRA只讀不寫。單子要不要開、怎麼寫，是你跟 RD 的事。
不替你決定提交 平台開的 session 能跑腳本、能寫檔，但 git 的寫入被擋下來—— 它們是無人看管的，而索引是整個工作目錄共用的：同一台機器上常同時開著好幾個 session， 一個去 git add 就會把另一個 session 正在改的東西一起暫存。
它改完檔，結果確認會列出「這段期間動了哪些檔」，提交與否由你決定。
⚠️ 這不代表 Claude 不能幫你 commit —— 你在終端機用的那個會， 只是一定先問過你、而且只送出自己動到的路徑。
不自己寫腳本邏輯接產品、匯出範本、體檢都是按鈕，底下跑的是 scripts/ 裡那幾支現成腳本。

東西都放在哪

手冊裡會一直看到「自動寫回檔案」。那些檔案就是下面這些—— 平台只是視圖，資料是你打得開、改得動、用 git 追得到歷史的純文字檔。 平台關掉，東西還在。

03一天長什麼樣

先看整體怎麼運作，後面每一節才知道自己在講哪一段。

什麼是 skill

skill 就是寫給 Claude 看的做事說明書。一支 skill 講一件事該怎麼做： 怎麼開 Bug 單、怎麼設計案例、怎麼收尾。它們放在 .claude/skills/， Claude 每次做事前會先讀對應的那一支。

為什麼這件事重要：skill 寫得好，Claude 做出來的東西就穩定； skill 沒寫，它就只能自由發揮。平台的任務按鈕，本質上就是「幫你載入對的 skill」。 你不用背它們的名字——按鈕已經配好了。

每一支 skill 在管什麼

下面這張表不用背——按鈕會自動載入對的那一支。想自己叫的話，在對話裡打 載入 /handoff 就行。

skill管什麼
handoff開工與收尾。接手時該先看什麼、卡在哪、哪些測試資料不能刪；收工時要更新什麼。
testcase-design要測哪些、測到多深。怎麼把一個功能拆成功能點、怎麼決定深度、期望值該從哪裡來。
browser-ops怎麼操作瀏覽器。語意定位、特殊元件的輸入陷阱、多人同時用站台會互踢。
ui-test怎麼把案例寫成 pytest。Page Object 放哪、命名怎麼取、跑完要產報告。
bug-reportBug 單怎麼寫。編號怎麼配、欄位有哪些、開單前要先問自己哪三件事。
jira-verify重驗修復的流程。抓單 → 對應本地單 → 走一次重現步驟 → 給結論。
⭐ 每張單還要驗連帶影響（side effect），而且順序固定：所有單的主訴求先驗完出報告，才回頭補驗 side effect——波及面的清單要等主項驗完才會準。沒補驗的一律寫成交接檔。
perf-test壓測怎麼跑。前置檢查、指標怎麼判、結論怎麼寫。
writeback學到的東西寫哪裡。這則知識該進機制文件、還是交接檔、還是記憶。
commit提交的規矩。同一台機器上好幾個 session 共用一份工作目錄時，怎麼只送出自己的東西。
<產品名>你自己的產品規範。接產品時會建一份空的，內容要你自己填——探索完之後把「不能忘的規則」寫進去。
產品 skill 一開始是空的，這是刻意的。沒有人比你更清楚你的產品。 探索完第一輪，就把「這個產品絕對不能搞錯的幾件事」寫進 .claude/skills/<產品>/SKILL.md—— 之後每一次對話都會自動帶上。

04每個功能的四段

每一個功能都走同樣四段：執行（從哪裡按下去）→ 狀態追蹤（跑的時候看哪裡）→ 結果（跑完在哪看）→ 下一步（拿這個結果可以做什麼）。

怎麼用這一節：先在這裡找到你要做的那件事，看完四段就知道整條路長什麼樣； 要看實拍畫面再往下翻到對應章節。「下一步」那一格是重點—— 它回答的是「做完之後呢」，而那正是最容易斷掉的一段。

▶ 跑自動化測試　工具 · UI 自動化測試

執行案例頁勾選要跑的 → 底部「執行選取（N）」； 或到工具 → UI 自動化測試填參數後按執行。
狀態追蹤自動跳到執行頁：四段進度（收集案例／執行中／產生 Allure／完成）、 百分比、通過／失敗／略過即時跳動、目前跑到哪一條、主控台尾巴。 總覽的運行中卡同步顯示。要停可以按停止或強制終止。
結果同一頁變成完成狀態：通過幾條、失敗幾條， 失敗案例逐條列出錯誤訊息與既有單（這條是不是已經有 Bug 單了）。 另有執行輸出與Allure 報告。所有執行都收進報告中心 → 執行紀錄。
下一步只重跑這 N 條（不用整批重來）／ 從失敗 run 開單（帶著 nodeid 與錯誤訊息起任務，先走開單前三問）／ 再跑一次／看 Allure 追細節。

🌅 開工接手　任務 · handoff

執行總覽或產品頁 → 開工接手。只有兩格：產品、今天想做什麼（可留白）。
狀態追蹤對話視窗打開並開始串流：先出現載入 skill、平台·get todos 之類的工具標籤，底下是會動的三顆點——看得出它還在做事。
結果一張「剩下的量／卡在哪」的表，加上結論。 發現交接檔本身缺東西時會交草稿，平台當場落檔並取編號 （畫面底下會出現「✅ 已自動寫入 …（編號 T2）」）。
下一步照著清單直接按下一個任務鈕，或到產品頁 → 待辦逐項展開。

實拍 → §06 開工接手

🔭 探索新功能　任務 · testcase-design ＋ browser-ops

執行總覽或產品頁 → 探索新功能。填產品、功能區塊、 安全邊界（可寫入／本次唯讀）、指定子帳號、風險假設。
狀態追蹤對話視窗串流。探索會真的開瀏覽器操作， 所以工具標籤裡會看到瀏覽器·click、瀏覽器·type 這類動作。 總覽的對話入口會顯示「N 條進行中」。
結果⭐ 產出會自動寫回檔案：機制文件／覆蓋矩陣進 docs/<產品>/ 並登記 docs/INDEX.md； 發現的缺陷進 docs/<產品>/bugs/；動過的測試資料寫進交接檔 §5。 到產品頁 → 文件／Bug／待辦就看得到。
下一步把摸熟的功能點寫成案例（→ 撰寫案例）／ 把「不能搞錯的規則」補進產品 skill／針對發現的缺陷去 JIRA 開單再回填單號。

實拍 → §06 探索新功能

📐 需求驗證　任務 · testcase-design ＋ bug-report

執行總覽或產品頁 → 需求驗證。要指出權威規格來源 （需求單／規格文件／PM 裁示）與需求內容，逐條比對。
狀態追蹤對話視窗串流。
結果一份驗證報告寫進 docs/<產品>/bugs/_reports/， 到報告中心 → 驗證報告看；不符規格的部分開成 Bug 單。
下一步報告可以打勾標記已看過（標題會加刪除線）／ 把沒驗完的範圍留進交接檔／針對缺陷去 JIRA 開單。
⛔ 實測與文件不符時，先問「有沒有人說要改」。 找得到變更聲明（RD 留言、PM 修訂、裁示）才更新文件； 只有「我量到不一樣」的話那是缺陷，要開單，不是改文件。 這是測試工作最嚴重的失誤型態——把缺陷改寫成規格之後，就再也沒有人會去驗它。

實拍 → §06 需求驗證

✍️ 撰寫案例　任務 · ui-test

執行總覽或產品頁 → 撰寫案例。填來源覆蓋矩陣與要轉成案例的功能點。
狀態追蹤對話視窗串流。它會開瀏覽器把案例真的跑一次—— 沒跑過的案例不算寫完。
結果案例自動寫進 tests/<產品>/， 寫完立刻用 --collect-only 檢查；收不起來就自動還原，不會留壞檔。 案例頁最上面會出現一條「新寫入待確認」，列出這批寫了哪幾條。
下一步在案例頁確認那一批／直接勾起來執行選取跑一次／ 把它掛到 Bug 單的 regression 欄（那一欄空著會被 lint 的 D10 抓）。

實拍 → §06 撰寫案例

🔍 驗 JIRA 修復　任務 · jira-verify

執行總覽或產品頁 → 驗 JIRA 修復，填單號（可多筆）。
狀態追蹤對話視窗串流；它會抓 JIRA 單、對應本地 Bug 單、走一次重現步驟。
結果驗證報告（報告中心 → 驗證報告）＋ 本地單的 status 更新。部分修復時會開新單承接殘留，舊單維持原狀。
⭐ 報告固定三區塊：驗證項目／驗證過程與結果／Side effect。 第一份報告出來時 side effect 只列項標「待驗」——那是刻意的， 主項全部驗完才回頭補，否則每張單都停在「部分完成」，你沒辦法對任何一張下決定。
下一步產品頁 → Bug → 待重驗／該關單兩個篩選會跟著變； 修好但沒有回歸案例的會落到缺回歸——那就是下一批要寫的案例。
還沒補驗的 side effect 會寫成交接檔，下次接手看得到。

實拍 → §06 驗 JIRA 修復

🐞 開 Bug 單（手動／從失敗 run）　任務 · bug-report

執行手動開 Bug 單在總覽（填現象、期望、環境）； 從失敗 run 開單在執行頁的失敗結果區（run、nodeid、錯誤訊息自動帶入）。
狀態追蹤對話視窗串流。它會先走開單前三問： 是規格還是缺陷／這現象是不是已經被查證過／樣本有沒有鑑別力。
結果判定該開的才配號落單（編號在寫檔那一刻才取，不會撞號）， 檔案進 docs/<產品>/bugs/。 ⭐ 判定不該開的話它會講清楚理由——這也是有效的結果。
下一步產品頁 → Bug → 點那一列 → 複製開單資訊貼到 JIRA → 開完回來回填 JIRA 單號，「漏開單」的數字當場少一個。

實拍 → §06 開 Bug 單、§08 回填 JIRA

🧾 收尾體檢　任務 · handoff ＋ writeback

執行總覽 → 收尾體檢。沒有參數要填。
狀態追蹤對話視窗串流；工具標籤會看到它把 get runs／get drafts／get bugs／get todos 都查過一輪。
結果一份「漏做了什麼」的清單：交接檔落後幾天、 跑過的 run 沒有對應紀錄、待補回歸幾張、草稿沒收掉幾筆。 ⭐ 這是單一個 session 看不到的東西——它跨 session。
下一步該補進交接檔的它會直接交草稿讓平台落檔； 它做不到的（改 Bug 單 frontmatter、撤掉草稿）會明講要你做什麼，然後才 commit。

💬 對話　問索引 · 起任務 · 提議執行

執行總覽主視覺腳下的對話入口，或左側 rail 的對話頁。
狀態追蹤訊息底下的工具標籤告訴你它查了什麼（平台索引／讀檔／搜尋）， 會動的三顆點表示還在跑。
結果回覆本身；有查索引的話數字是當下真的，不是它記得的。
下一步它會直接寫「到產品頁的 Bug 分頁看」這種指路，照著點就到了； 要它跑東西的話會出確認卡——平台不會替你按。

⚙ 工作區操作　設定 → 工作區

執行設定 → 工作區：接一個產品／裝通用 memory／清空原型產品／匯出範本給同事。
狀態追蹤同步命令，按下去按鈕轉圈並逐秒計時， 旁邊寫明上限幾秒、離開頁面會中止。
結果就地顯示，含它實際下的那一行命令與完整輸出； 離開再回來還原成「上次執行」，不會消失。
下一步結果下方會出現去哪裡的按鈕（例如接完產品 → 去那個產品頁）。 ⛔ 平台不會自動跳轉——你可能還想看輸出。
兩個高風險命令會要你打字確認： 清空原型產品與匯出範本都會刪東西（匯出會清空目標目錄）。

設計原則：用 AI 是為了讓你少做事，不是多一份「審核」的工作。 所以低風險的產出一律自動存，你事後看。只有兩種情況會停下來等你。

哪些自動、哪些要你按

整份蓋掉既有文件要你按 會蓋掉先前寫進去的內容 —— 可能是你自己，也可能是另一個 session 剛寫的。

11安全邊界

這一節不長，但每一條都是有代價才學到的。

對象可以做什麼說明
測試環境的 Web／UI直接做 下注、改設定、建帳號都可以。為了取證而寫入是測試的常態，逐次請示只會拖慢。
測試環境的資料庫一律唯讀 查詢可以，改值不行。DB 改值會繞過所有應用層邏輯，改出來的狀態未必是系統真的能產生的狀態——那樣驗到的結論可能根本不成立。
預備／正式環境不碰 預備環境通常已經給客戶試用了。要用需要逐次授權，且授權只適用那一次。
會影響別人的操作先問 開獎、結算、反結算、關盤這類會波及其他人的動作。判準是「會不會影響到別人」，不是操作本身危不危險。

平台自己的界線

它拿不到為什麼
git 的寫入 2026-08-25 起 session 有 shell 與寫檔——沒有的話它跑不了 stamp_shots.py 搬截圖、跑不了 lint_docs.py 收尾、也沒法當下取號，等於做不到規範。 改成擋真正該擋的兩件事：git 的寫入（add／commit／stash／push）與 刪到自己工作目錄以外。唯讀的 git status／diff／log 照用。
配號這一步Bug 單的配號仍由平台在落檔那一刻執行——這樣配號才會落在「寫檔那一刻」，兩個任務同時跑也不會撞。
git 索引索引是整個工作目錄共用的，而同一台機器上常同時開著好幾個 session —— 一個去暫存，就會把別的 session 正在改的東西一起帶走。要不要提交一律由人點頭。
寫 JIRA只讀不寫。
⛔ 用完把測試資料還原——但有一個例外。 據以開立 Bug 單的資料要保留，那批資料就是那張單的重現環境。 還原掉的話，RD 照著重現步驟走會看不到現象。保留到單子關掉為止， 並在交接檔的測試資料現況登記「刻意保留、屬哪一張單」。
⭐ 上面圖 6-2 的開工接手就是在做這件事——它主動要求把 CRUX-001 的重現資料登記起來。

12卡住的時候

現象怎麼辦
開不起來 先跑 scripts\setup_test_env.ps1 看總結表——平台需要 flask／psutil／requests。
任務按鈕是灰的 找不到 claude 執行檔。到設定 → Claude 看它說什麼，那一頁直接寫著怎麼裝。其餘功能照用——不接對話也可以只用索引與執行。
畫面上的數字都不動了 表頭會變紅並寫「平台已斷線 —— 畫面上的資料是舊的」。服務重開之後會自動連回並跳提示。
接完產品但看不到 重新整理一次。儀表板是開頁時載入的。
跑完發現一堆紅的 先看失敗案例那一區的既有單欄——已經有單的就不是新壞的。測試失敗 ≠ 缺陷，先確認不是測試碼或環境問題。
執行中途離開頁面 run 型不受影響（它在背景跑，回來還看得到）。同步命令會中止——按鈕旁邊有寫。
平台被關掉時正在跑東西 下次啟動會自動收拾：那些執行標成已停止 · 中斷而不是「失敗」，進度保留原樣——這樣你才看得出它跑到哪裡被打斷。
兩個人搶同一組測試帳號 站台通常是「同帳號他處登入即踢掉前者」，症狀是令牌過期。跑測試前先確認用的子帳號跟別人分開，任務表單的指定子帳號就是為此。

13接新工具與新產品

⭐ 這一節是整份手冊裡最該用到的一節。 範本給的那幾顆按鈕與那一支工具只是開頭 —— 下面三件事都不必改平台程式， 各自改一份 JSON 就會反映到畫面上。

再接一個產品

設定 → 工作區 → 接一個產品，跟第一次一模一樣（見 五分鐘上手）。 接幾個都可以，儀表板會多一根柱子。

接一支自己的工具

工具是宣告出來的，不是寫死在平台裡的。在 tools/test_platform/registry/ 放一份 <id>.tool.json， 說清楚「怎麼跑、要問哪些參數、結果怎麼顯示」，它就會出現在工具頁——不必改平台程式。

宣告什麼意思
kindcli／pytest／http——它是哪一種東西。
commands[]每個命令的固定命令列前綴，加上要問人的欄位。
moderun（長時間，會進報告中心、可監控可停止）或 sync（秒級到分鐘級，結果就地顯示）。
next[]⭐ 跑完之後可以去哪——就是本手冊講的「下一步」。沒宣告的話跑完就只是一段文字。
danger會寫入測試站的標 high，介面才會要人打字確認。
gate跑之前的提醒（前置條件、會跟誰搶站台）。只提示不硬擋。

不想從頭寫的話，註冊表頁的「＋ 接一支新工具」會產生骨架並當場驗證。 ⚠️ 骨架建好之後還是要自己補欄位——平台不會替你猜，猜出來的欄位會變成「填了不生效」。

加一顆自己的任務按鈕

任務也是宣告式的。內建的放在 tools/test_platform/tasks/， 你自己加的放 tasks/custom/——兩者載入方式一樣， 分開只是為了讓範本更新時不會把你的東西算成差異。 一顆任務要宣告：要載哪幾支 skill、要問哪些欄位、送出去的提示長什麼樣、 額外放行哪些工具，以及可選的預設模型。

14附錄：Claude 用量

總覽最上面那條的中間一段。與測試流程無關—— 只是順手讓你知道額度還剩多少，不看也不影響任何功能。

它同時給你兩種用量，因為兩種各有各的缺點：

正常情況顯示百分比 ＋ 進度條 ＋ 倒數（≥70% 轉琥珀、≥90% 轉紅）。 額度每 5 分鐘自動更新一次；右上角的 ↻ 可以立刻重打，不必等。 角標是你的額度層級（例：Max 5×）。點整段進 設定 → Claude 看完整明細。

⛔ 這條會讀你的 OAuth token。 平台從 ~/.claude/.credentials.json 取 token 去查你自己帳號的用量 —— token 只在記憶體流動：不回傳瀏覽器、不落檔、不進 log、不進錯誤訊息（有測試釘住這四條）。 不想要就在 platform_config.local.json 設 claude.live_quota: false， 它會退回下面那條路。
⚡ 退回本機快照時怎麼辦：在 Claude Code 裡打一次 /usage。 那份快照是 Claude Code 自己抓的，不會自己更新（實測曾 54.5 小時沒動）—— /usage 是本機指令、不消耗額度，打完按 ↻ 就會看到新數字。 ⛔ 別指望背景 session 去刷：實測 claude -p "/usage" 不會更新快照 （slash 指令在 print 模式不執行），定時起 session 只是為了看額度而消耗額度。
⛔ 兩種用量不要互相換算。 額度的計費權重不是 token 的簡單相加。另外額度是帳號層級的， token 統計因此涵蓋這台機器上所有工作區，不只這一份。
