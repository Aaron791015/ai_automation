# 任務模板（`tasks/*.json`）

每個任務 ＝ 一顆按鈕：**填幾個欄位 → 開一個 Claude session → 帶著對應的 skill 與提示開始工作**。

## 為什麼要有這一層

平台的價值在「**聚合與觸發**」，而測試工程師的日常有一半是**創作**
（探索、設計、判斷、寫報告）—— 那些是 Claude session 在做的事。
任務模板就是兩者的接點：**平台知道你要做什麼、帶好上下文，把判斷交給 session**。

## 目錄分界（★ 範本化的關鍵）

```
tasks/          內建 —— **通用層，該同步**（隨範本匯出、納入 --compare）
tasks/custom/   你自己加的 —— **個人層，不同步**（不匯出、compare 略過）
```

兩者**載入方式完全相同**，UI 上也不區分。分開只是為了範本化的歸屬 ——
不分的話，你加一個自己的任務按鈕，`--compare` 就會報一筆你看不懂的差異。

## 欄位

| 欄位 | 說明 |
| --- | --- |
| `id` | 唯一識別，同時是檔名 |
| `label` / `icon` / `order` | 按鈕的顯示 |
| `subtitle` | 一句話說明「什麼時候按這顆」 |
| `skills[]` | 要 session 載入哪幾支 skill —— ⭐ **這是「skill 是平台的大腦」的實際落點** |
| `scope` | `product`（要選產品）或 `workspace` |
| `entry[]` | 按鈕出現在哪：`overview`／`product`／`run` |
| `writes` | `draft`（產草稿，寫檔由平台做）或 `none`（純唯讀） |
| `fields[]` | 表單欄位，格式同 registry 的 `params.fields`（重用 `ui/form.js`） |
| `prompt_template` | 送給 session 的第一則訊息，`{欄位key}` 會被替換（單層大括號） |
| `allowed_tools[]` | 額外放行的工具（預設只有唯讀＋平台 MCP） |
| `timeout_minutes` | 單次上限（分鐘）。表單有 `timebox` 欄位時以表單為準，兩者都沒有才用 30 |
| `compact_tokens` | **邊界壓縮門檻**（token）。context 超過它時，平台會在「回覆結束、交還給人」那一刻換一份較短的工作記憶（`core/session_compact.py`）。省略＝用設定檔的 150000；填 `0` ＝ 這個任務不壓縮。<br>⭐ 證據會邊做邊落檔的任務（如 `write_cases` 寫進 `tests/`）可以壓得比證據留在 context 裡的（如 `explore`）兇 |
| `model` | **選填**，這個任務的預設模型（`sonnet`／`opus`／…）。沒宣告就用平台設定的 `default_model`。<br>⚠️ 只是**預設值** —— 人在任務框的「執行設定」仍可改；模型在 session 建立時決定，中途不能切 |

### `{欄位}` 之外，模板還可以用兩個衍生值

| 佔位 | 由 `core/tasks.py` 產生 | 用途 |
| --- | --- | --- |
| `{boundary_label}` | 依 `boundary` 欄位值翻成人看得懂的字 | 標題那一行 |
| **`{boundary_rules}`** | 依 `boundary` 展開成**整段條款** | 見下方第 3 條 |


## ⛔ 三條硬紀律

1. **`writes: draft` 的任務，session 不直接寫檔** ——
   它產草稿，**寫檔由平台執行**（`gen_bug_index --next-id` 配號也在那一刻）。
   這是 `core/bug_draft.py` 檔頭記載的 2026-08-21 裁示，套用到所有寫入型任務：
   > 拆成草稿／開單兩段…**測試失敗 ≠ 缺陷**…而 `CLAUDE.md` 明訂 Bug ID 永不回收

   ⭐ **2026-08-25 更正**：這條講的是「**Bug ID 何時配號**」，不是「能不能寫檔」。
   session **現在有 shell 與寫檔**（使用者裁示：要能做到與終端機幾乎相同的事）——
   否則它跑不了 `stamp_shots.py`／`lint_docs.py`／`next_todo_id.py`，
   照不了 skill 的規範（實際後果：8 張佐證整批遺失、知識回寫做不完）。
   草稿／落檔那條動線**照舊**：它管的是需要人判斷的那一刻。
   邊界改由 `guard/pretool_guard.py` 守（⛔ git 寫入、⛔ 刪到自己家以外）。

2. **`prompt_template` 要點名 skill，不要重寫方法論** ——
   寫「載入 `bug-report`，走 §3.9 開單前三問」，
   不要把三問的內容抄進 prompt。抄了就會與 skill 分岔。

3. ★ **會操作站台的任務，一定要用 `{boundary_rules}` 而不是自己寫一句話**
   （2026-08-23 新增）。

   > **踩過的坑**：探索任務原本只把邊界翻成一個標籤（「安全邊界：可寫入 QAT」），
   > session 拿到之後**仍然全程唯讀** —— 它讀了 `CLAUDE.md` §5 裡「執行前先說明會做什麼」
   > 那一類句子，而它**問不到人**，於是選了最保守的解釋。
   > 結果整場探索只驗得到讀得出來的東西（欄位有沒有 `pattern` 屬性），
   > **一條會改狀態的規則都沒驗到** —— 而金流邏輯全在那一側。

   `{boundary_rules}` 展開的是 §5 授權表的結論：QAT 的 Web／UI 寫入**已預先授權、
   不必逐次請示**，同時把三條紀律（不做波及他人的操作、不動他人資料、
   用完即還原但**據以開單的保留**）一起帶進去。

   ⚠️ 連帶地，提示裡要寫「**你不能寫 repo 裡的檔案**」，
   ⛔ 不要寫成籠統的「你不能寫檔」—— **站台寫入與寫 repo 檔案是兩件不同的事**，
   混在一起講，session 會把兩者一起停掉。
