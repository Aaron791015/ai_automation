# 新綜合 UI 元素對照

> **本檔是「畫面上實際顯示什麼字」的唯一權威來源。**
> 寫測試案例時，凡出現頁面名稱、欄位名稱、按鈕、開關、玩法、表頭、提示文字、設定區塊，
> 一律先查本檔或直接看實際 UI 畫面，**不可**依 Python 變數名、locator 名稱、API 欄位名、
> 舊案例措辭或自行理解去翻譯／推測 UI 名稱。規則見
> [`新綜合_測試案例撰寫規則.md`](新綜合_測試案例撰寫規則.md) 第 2 步。

> ⚠️ **新增條目時務必連同「所屬結構家族／適用範圍」一併寫清楚**——同一頁面常有
> 「看起來像同義詞、其實是不同結構各自的正式名稱」的情況（見下方「飛單選項明細設置」
> 一節的 `每選項自留上限` vs `共用自留上限`），把其中一個當成另一個的簡寫或誤寫是常見錯誤來源。

### 「飛單選項明細設置」頁欄位 —— ⚠️ 分兩種結構家族，欄位名稱不同

「飛單選項明細設置」共 25 個玩法分類，分兩種結構家族，**各自的自留上限欄位名稱不一樣**，
不可互相取代或當成同一件事的兩種寫法：

| 結構家族 | 涵蓋玩法（15＋10＝25） | 本結構專用的欄位 UI 名稱 |
| --- | --- | --- |
| **標準選項清單型**（15 個） | 特码、正码、正特码、两面、生肖中、生肖不中、半波、特肖、尾数中、尾数不中、色波、七码、五行、一肖量、尾数量 | 占成、**每選項自留上限**、自動飛單 |
| **組合型**（10 個） | 连码、过关、六肖、连肖、连尾、不中、多选中一、特平中、合肖、比大小 | **組合占成金額**、**共用自留上限** |

> ⛔ **常見錯誤**：把「每選項自留上限」寫成「共用自留上限」，或反過來——
> 兩者是不同結構家族**各自的正式 UI 文字**，寫案例時要先確認在測哪個結構家族的玩法，
> 再套用對應欄位名稱，不可挑一個當通用說法。

後端是同一個 API 資源，25 個分類只差 `gameId`／`playTypeId`，UI 差異純屬前端客製化渲染。
