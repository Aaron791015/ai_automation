# 新綜合 UI 元素對照

> **本檔是「畫面上實際顯示什麼字」的唯一權威來源。**
> 寫測試案例時，凡出現頁面名稱、欄位名稱、按鈕、開關、玩法、表頭、提示文字、設定區塊，
> 一律先查本檔或直接看實際 UI 畫面，**不可**依 Python 變數名、locator 名稱、API 欄位名、
> 舊案例措辭或自行理解去翻譯／推測 UI 名稱。規則見
> [`新綜合_測試案例撰寫規則.md`](新綜合_測試案例撰寫規則.md) 第 2 步。

> ⚠️ **新增條目時務必連同「所屬結構家族／適用範圍」一併寫清楚**——同一頁面常有
> 「看起來像同義詞、其實是不同結構各自的正式名稱」的情況（見下方「飛單選項明細設置」
> 一節的 `每選項自留上限` vs `共用自留上限`），把其中一個當成另一個的簡寫或誤寫是常見錯誤來源。

## 1. 飛單設置 / 飛單選項明細設置

### 頁面名稱

| UI 顯示名稱 | 說明 |
| --- | --- |
| **飛單設置** | 公司層「系統設置」子選單之一 |
| **飛單選項明細設置** | URL `/setting/lay-off-setting-detail`，API `GET/PUT /api/LayOffSettingDetail?gameId=&playTypeId=`。與「飛單設置」是互斥的父子關係——本頁總開關「啟用飛單選項明細」開啟時會跳確認框：「原系統設定－飛單設定中，飛單設定的金額將會失效，並且自動出貨將變更為手動模式」 |

> ⚠️ **窄視窗導覽**（2026-09-02 QAT、1280×720實測）：頂部「系统设置」會被 Element Plus
> 收進最後一個「…」溢出選單，不再是直接可見的頂層menuitem。自動化需先展開
> `.el-menu--horizontal > .el-sub-menu` 的最後一項，再點擊「系统设置」；直接等待頂層文字會逾時。

### 「飛單設置」頁欄位

| UI 顯示名稱 | 適用範圍 |
| --- | --- |
| 自留口徑（占成型／仓位型） | 全部玩法 |
| 每選項自留上限 | 全部玩法（「飛單設置」頁層級） |
| 自動飛單（開關） | 全部玩法；與「開啟飛單選項明細設定」互斥（明細設定開著時本開關鎖住不可互動） |
| 最小飛單額 | 全部玩法 |
| 開啟飛單選項明細設定 | 全部玩法 |

### 「飛單選項明細設置」頁欄位 —— ⚠️ 分兩種結構家族，欄位名稱不同

「飛單選項明細設置」共 25 個玩法分類，分兩種結構家族，**各自的自留上限欄位名稱不一樣**，
不可互相取代或當成同一件事的兩種寫法：

| 結構家族 | 涵蓋玩法（15＋10＝25） | 本結構專用的欄位 UI 名稱 |
| --- | --- | --- |
| **標準選項清單型**（15 個） | 特码、正码、正特码、两面、生肖中、生肖不中、半波、特肖、尾数中、尾数不中、色波、七码、五行、一肖量、尾数量 | 占成、**每選項自留上限**、自動飛單 |
| **組合型**（10 個） | 连码、过关、六肖、连肖、连尾、不中、多选中一、特平中、合肖、比大小 | **組合占成金額**、**共用自留上限** |

> ⛔ **常見錯誤**：把「每選項自留上限」寫成「共用自留上限」，或反過來——
> 兩者是不同結構家族**各自的正式 UI 文字**，寫案例時要先確認在測哪個結構家族的玩法，
> 再套用對應欄位名稱，不可挑一個當通用說法。

後端是同一個 API 資源，25 個分類只差 `gameId`／`playTypeId`，UI 差異純屬前端客製化渲染。

#### 標準選項清單型「選項1」對照表（2026-09-02 實測核對，香港六合彩）

案例撰寫常用「選項1」指代「选项」欄位（表格第 1 欄）由上而下的第 1 列——這不是固定的
「號碼 01」，每個玩法的「选项」欄內容完全不同，寫案例時**不可只寫「選項1」就當作講清楚了**，
要嘛直接寫出下表對應的實際內容，要嘛在該案例的測試範圍/判準裡指回本表：

| 玩法 | 「选项」欄位第1列實際內容 |
| --- | --- |
| 特码 | `1` |
| 正码 | `1` |
| 正特码 | `1` |
| 两面 | `正1特大` |
| 生肖中 | `鼠` |
| 生肖不中 | `鼠` |
| 半波 | `特码红大` |
| 特肖 | `鼠` |
| 尾数中 | `0` |
| 尾数不中 | `0` |
| 色波 | `正1特红波` |
| 七码 | `单0` |
| 五行 | `金` |

⚠️ 上表只在**其他彩種尚未逐一核對過**——目前只實測了香港六合彩，英國天天彩／賓果六合彩的
「选项」欄第1列內容假設一致（同一批玩法名稱、同一套前端渲染邏輯），但沒有實測驗證，
差異未知即為缺口，追蹤見 `新綜合_驗證交接.md`。
組合型再依 `table=10`（连码／不中／多选中一／特平中）與 `table=0`（过关／六肖／连肖／连尾／合肖／比大小）
分兩種子變體，但兩個子變體的 UI 欄位名稱相同（皆用「組合占成金額」「共用自留上限」）。

兩個無子項玩法，共 55 個組合型目標。完整 `playTypeId` 已由

根因未查。
