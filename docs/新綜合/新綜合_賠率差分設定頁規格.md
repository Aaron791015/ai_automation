## 適用範圍與欄位結構

- 三彩種共用：香港六合彩（markSix）、英國天天彩（ukLucky7）、賓果六合彩（bingo6）。
- 適用賠率差分設定頁；依既有授權與權限存取各代理／會員設定，不因本文件放寬操作權限。
- 表頭包含「玩法」「赔率差分」「剩余差分」。每個玩法有主差分輸入及對應剩餘值；有副欄者，另須有副差分輸入與其對應剩餘值，不能用單一主欄代替。
- 每彩種101個玩法設定列、101個主欄及15個副欄，共116個差分輸入欄。分類標題不計玩法列，剩餘差分顯示不計輸入欄數。
- 「兩面」必須存在；五不中至十二不中每列只有一個輸入欄，不設本命年副欄。過關沿用既有裁定，不支援賠率差，不列入。
- 下表為完整列舉順序，尚未裁定畫面必須採同一排序、分組位置或標點樣式；不得把文件順序直接當UI排序缺陷。

## 操作日誌（2026-09-29 Aaron確認）

- **已確認要求**：賠率差分設定成功變更後，須記錄於「操作日誌」。適用三彩種、公司後台及各層級中間商後台，包含適用的主／副差分設定。
- **入口一：帳號日誌**：公司後台或各層級中間商後台 → 用戶管理 → 目標帳號（aaa111～aaa999及會員aaa010）→「日誌」，須可查到該帳號的賠率差分變更。
- **入口二：依類型篩選**：公司後台或各層級中間商後台 → 操作日誌 →「類型」下拉選單 →「賠率差分設定」，須可查到權限範圍內的賠率差分變更。
- **權限與一致性**：公司與中間商均依既有管轄／查閱權限驗證，不要求中間商存取上級或非管轄帳號；同一筆成功變更須在上述兩個有權查閱的入口對應一致，不能只驗其中一處就視為完成。
- **內容依據**：Aaron提供的新版設計文件 `odds-gap_1.md` §6.1 已要求稽核記錄玩法與新舊差分；驗證時以設定前值、保存結果與保存後讀回值作獨立對照，不能只看「有一列日誌」即判通過。實際UI名稱、欄位與定位方式已於2026-09-29實測核對（「操作日志」、用户管理→「日志」，「类型」選「赔率差分设定」），見[UI元素對照 §2.1](新綜合_UI元素對照.md)。
- **未補定的邊界**：同值保存、保存失敗是否留紀錄、多欄保存如何分筆，以及授權開關／平台開關是否歸入同一類型，本次未指定；保留待確認，不阻擋成功差分變更的兩入口驗證。測試還原若成功改回差分，同樣屬設定變更，亦應留下可追溯紀錄。
- **驗證狀態**：B108 已建立（`tests/xzh/test_odds_gap_operation_log.py`）。2026-09-29 冒煙 1 組（aaa111 改 aaa222、宾果六合彩、116 欄）通過：修改與改回各一批 101 筆，公司與 aaa111 兩入口皆查得到同一批、前後值與讀回值一致；三彩種 × 19 組完整實跑待排，進度見[驗證交接](新綜合_驗證交接.md) T66。
- **實測現況（未定邊界的觀察，不作判準）**：一次保存改多個玩法時併成同一批（畫面「共 N 笔」），每個玩法一筆、主副差分同筆。
