- 沒有中獎樣本、資料缺漏、未開盤都不算通過，分開列。
- 正在執行、報告還沒寫完的批次不算進結果，只註明進行中。
- B104 已於 2026-10-01 移除，不列入、不當缺口。
- 全量唯讀通過不等於全欄保存通過；代表寫入通過不等於全玩法寫入通過。
- 平台「赔率差上限」比例若和上次全量驗算時不同，B92 視為需要重跑。

## 判斷原則（為什麼這樣定）

1. **設定端三彩種共用同一套欄位與公式，投注與結算是另一段程式。** 設定頁三彩種通過，不能推到下注、凍結、結算；賓果投注通過，也不能直接推到香港與英國。
2. **香港、英國不必複製賓果的全分支。** 定價規則依玩法類型而定，賓果已覆蓋全部分支；另外兩個彩種的風險在部署與各彩種資料（例如注單分表缺欄、報表無資料），每種定價類型取一個代表就抓得到。
3. **唯讀能全量的就全量，寫入與下注用代表。** 唯讀全量只要幾分鐘；逐欄寫入與追中獎樣本成本高，只有規則因欄位而異時才值得逐欄。
4. **輸入檢查、＋／− 按鈕、保存是共用元件。** 元件規則不會逐欄不同，逐欄重複只增加時間。
5. **下注價可以完全確定，中獎不能。** 下注當下的賠率每注都能驗；結算需要中獎樣本，低機率分支以「同機制的另一分支已證實」類推，標為風險接受而不是通過。
6. **收益公式依定價類型分支，不依玩法（2026-10-01 Aaron 同意）。** 定價類型五種：單欄、主副擇一、連肖／連尾、雙套、七碼。玩法之間會出錯的是「設定對應到哪個玩法」，這段由全玩法快照與每玩法一注的下注價覆蓋，不需要中獎；結算只要每彩種、每種類型有中獎樣本。任何一種類型出現結算不符，該類型就擴大到全部玩法追樣本，不沿用風險接受。
