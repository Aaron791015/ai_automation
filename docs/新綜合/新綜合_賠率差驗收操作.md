## 凍結稽核契約

`XZH_GAP_FROZEN_AUDIT` 指向 JSON。僅設定此變數不會解除 BLOCKED。
`XZH_GAP_REPORT_DAY` 選擇報表日期，未設定使用當日；A/B 新下注使用當日，不以歷史資料充數。
來源必須是可審查的唯讀原始匯出；不能從收益反推有效差，不能以當前設定代替下注凍結資料。

根物件需有 `schemaVersion: 1`、`scope`、非空 `records`。

| 部分 | 必要欄位／順序 |
| --- | --- |
| scope | `date`、`gameIds`、`memberAccount`、`chain`、`settlementState: "settled"`、`complete: true`、完整且不重複的 `betIds` |
| 逐注身分 | `betId`、`gameId`、`playTypeId`、`selection`、`issue`、含時區的 `betAt`／`settledAt`、`reportDate`、`memberAccount`、`chain` |
| 結算輸入 | `betAmount`、`companyShare`、`agentShares`（一至九級共9值）、`diffs`（公司至九級共10值） |
| 產品結算實值 | `outcome`＝`won`／`lost`／`refund`；`actualGapMoney`（一至九級共9值） |
| 來源 | `inputSource`、`settlementSource`：相對稽核檔的不同 JSON 檔案；每個來源須能依注單ID唯一定位並核對身分及相應數值 |
| 定價驗證 | `companyResolvedOdds`、`minOddsAtBet`、`chainGapsAtBet`（aaa111 設定列至 aaa010 設定列，共10值，已套當時授權）、`frozenOdds` |
| 特殊玩法 | `rule`、`frozenMainOddsGap`、`frozenSubOddsGap`，依分支追加下述原始證據 |

來源 JSON 可為單一注單物件、注單陣列，或含 `records` 的物件。數值可用十進位字串；拒絕 null、NaN、Infinity 或缺層。
`chain` 必須是完整的 `aaa111, aaa222, …, aaa999, aaa010`；每筆及 scope 都核對。
完整性另與線上已結算注單全部分頁、注單ID、玩法、選項、期號、投注額、結果、占成核對。
報表按各彩種完整範圍比較；報表會員數、注數、投注額不等於選定會員完整注單時列 BLOCKED，不能拿部分注單合計比整份報表。

特殊分支：

- `standard`：一般玩法；不能將特殊玩法標成一般分支。
- `single-main`／`single-sub`：生肖中／不中、尾數中／不中、特肖、五行；核對未用分支及實際凍結主副差。
- `linked-main`／`linked-sub`：連肖及連尾依**整注成交的贏家成員**（各成員套用差分與下限後，會員最終價最低者）分支，不是只看選項是否含副標籤（2026-09-29 依新文件更新，見《賠率差公式》使用條件節）。贏家為连肖「马」或连尾「0」→ `linked-sub`：副鏈／副下限，主凍結為0，副凍結核對副鏈有效合計；贏家為一般成員（即使注單含马／0尾）→ `linked-main`：主鏈／主下限，副凍結必須為 null。標分支前須以下注當下各成員套用差分與下限後的會員最終價判定贏家，不能只憑選項推定。`odds_gap_audit.py` 已有兩種分支，但尚未檢查「含马／0尾卻判 main」的贏家依據。
- `dual-main`／`dual-sub`：二中特及三中二；`otherPricing` 必須有另一側完整的定價五欄（解析賠率、最低、10層設定、凍結賠率、10層有效差），並核對兩側凍結合計及 `isSubOddsWin`。
- `seven`：`sevenRepresentative=k`，`sevenLeafGaps` 包含 `odd{k}`、`big{k}`、`even{7-k}`、`small{7-k}` 的實際非零同步證據。
- 每彩種另需不截斷與觸及最低值的樣本；截斷逐層按最深層優先縮減驗算。驗縮減順序須至少兩層原差分非零、且未全部縮為零，才足以區別深層與淺層誰先縮。

B88／B100 另需 `XZH_GAP_BET_PLAN`，依 gameId 指定 `playTypeId`、`field`（oddsGap/subOddsGap）、前台 `category`、`optionIndex`、`amount`，必要時提供 `subItem`。
UI 投注僅送一次；回應不明只留待核對紀錄，不盲目重送。外部稽核來源需隨自然結算更新，`XZH_GAP_SETTLEMENT_TIMEOUT` 預設120秒；不操控共享開獎或結算。
A/B 必須符合 A下注→設定保存讀回→B下注，兩筆保留不同有效凍結差，且有可辨別九層收益的中獎樣本；下注後設定先還原再等待結算。
