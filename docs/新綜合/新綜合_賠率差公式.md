## 設定與投注公式

設定差分 `odds_gap`／`sub_odds_gap` ≤ 0，至小數4位；本級實得差 `diff_N` ≥ 0，單位是賠率，尚非金額。

```text
差分總合上限 = (玩法基準賠率 − 玩法最低賠率) × odds_gap_cap_rate
剩餘可扣差分 = 差分總合上限 + 自身差分 + 祖先鏈差分合計

玩家凍結賠率 = max(min_odds, 公司層解析賠率 + 鏈上生效差分合計)
本級拿到的賠率 = 上級拿到的賠率 + 本級列生效差分
diff_N = 本級拿到的賠率 − 直屬下級拿到的賠率（採下限截斷後有效值）
```

- 公司層解析賠率包含基準、盤口、跳水與手動調整；剩餘公式取 `odds_setting.odds` 基準，兩者不可混用。
- 平台 `odds_gap_cap_rate` 範圍0～1。**實際來源依Aaron於2026-09-17指定：平台帳戶管理 → company1 → 編輯 →「赔率差上限」百分比**；目前QAT選單實際名為「租户管理」。本日唯讀看到80%，換算比例0.8；後續每次重讀，不固定寫死80%。`Settings/Global`不是此公司上限來源，不能從剩餘結果反推比例。剩餘額度為顯示用途；文件明訂儲存不檢查超扣，增加伺服器驗證仍屬待決，不能當已生效規則。
- 下限截斷由最深層（最靠近玩家）的差分先縮減，再往上；凍結截斷後有效差，不可直接以原設定絕對值代替 `diff_N`。
- 副層以副賠率及副差分計算，下限使用 `sub_min_odds ?? min_odds`。
- 差分可於期中即時異動，但每筆投注各自凍結；結算只讀凍結值，不回查當前設定。
- **副差分未設即為0，不會改用主差分**：成交在副層的注單，若鏈上某層只設主差分、副差分空白，該層對這注不扣差分（2026-09-29 新文件）。
- **代理後台盤面的「公司赔率」已含一級代理差分**：盤面公司赔率＝公司解析值＋一級代理差分，注單記錄的公司賠率（`companyOdds`，成本基準）則不含差分，兩者相差一個一級代理差分屬正常。例：公司解析10、一級代理設−1 → 盤面公司赔率9、注單公司賠率10（2026-09-29 新文件「一級代理調賠疊加次序（已確認）」）。
  > ⚠️ **實測不符，見 `Snotra-019`**（2026-09-29：aaa111／aaa222 即时盘面宾果特码「赔率」41.993，未含 aaa111 差分 −1.1；畫面欄名為「赔率」而非「公司赔率」）。

例如公司層解析賠率49、最低1、生效差分−2與−3：玩家賠率 `max(1, 49−2−3)=44`。

## 投注期行為（曝險與拒單）

- 曝險如實反映：`max_payout` 以**含差分後**的玩家凍結賠率計算，派彩真的變低。`company_share_amount` 與跳水輸入不受差分影響。
- 拒單容差：玩家端送出的 `clientOdds` 已含自己的差分，伺服器以同口徑重算，沿用既有 `EnsureOddsNotDegraded` 比對。上級在玩家瀏覽期間把差分調得更低會觸發 `OddsChanged` 拒單，與跳水降賠拒單是同一既有行為。
- 定價快照 `BetPricingSnapshot` 帶 `oddsGapTotal`（生效差分合計）與下限截斷旗標，稽核可分解成「公司層解析值 → 差分 → 凍結值」。
- 廣播 `OddsChangedEvent` 仍送公司層最終值，不含差分；玩家前端自行以差分合計疊加。成本端 `company_odds` 不含差分。

## 結算公式

N 為代理層級1～9；以下占成金額均取 `bet_item` 凍結欄，缺席層不產生收益。

```text
remit(N) = bet_amount − holding_pre_chain_share_amount − holding_post_chain_share_amount
                      − Σ[j=N..9] agent_j_share_amount
gapMoney(N) = remit(N) × diff_N

δ(N) = gapMoney(N) − agent_N_share_amount × Σ[j>N] diff_j
δ(Company) = −company_share_amount × Σ[j=1..9] diff_j
δ(Company) + Σ[N=1..9] δ(N) = 0
```

- 僅贏局產生 `gapMoney` 與 δ；輸局、和局退本均為0。
- 上繳金額包含公司與更上層代理的占成；不能漏掉公司，不能以占成比例直接代替金額。
- **自營總控公司要先扣總控兩段佔成**（2026-09-29 新文件）：`holding_pre／post_chain_share_amount` 是投注時凍結的總控鏈前、鏈後佔成金額；公司上面沒有自營總控時兩者恆為0，公式退化回「投注額 − 本級及以下佔成」。漏扣會讓代理賠率差偏高、Σδ≠0。此時「公司＋九層佔成＝投注額 − 總控兩段」，不再等於投注額。
- δ 是併入既有輸贏的修正量；`gapMoney` 是報表收益欄，不能再把收益重複加一次。
- 落點分開看：δ 直接併入既有的 `*_result_amount`（總帳一致，報表不必自行推算），`gapMoney` 聚合進 `report.selection_win_loss` **與** `report.player_win_loss` 兩張表的 `agent{1..9}_odds_gap_amount`，供報表顯示「賺取賠率差」欄。玩家派彩 `payout` 與退水欄不動。
- **哪張報表讀哪裡**（2026-09-29 新文件）：玩法報表與按號碼鑽取讀 `selection_win_loss`；佔成報表與我的佔成報表讀 `player_win_loss`（含 scope 根的直屬會員投注）。佔成報表以 scope 根層為錨、我的佔成報表以觀看者層為錨；**以公司為錨時此欄恆為0**；**未結算模式不提供此欄**。
- 各層賠率差只入報表，不直接改代理餘額或帳變；玩家派彩依凍結賠率計算，跨層修正不再更動派彩。
- 飛單的 `share_delta` 不參與 remit，賠率差歸屬不隨飛單承接層轉移。

例如投注1,000、本級及以下凍結占成合計600、有效實得差2：`remit=400`，中獎時 `gapMoney=800`；這不是直接存入餘額的金額。同一注若公司上有自營總控、總控兩段佔成合計100：`remit=1,000−100−600=300`，`gapMoney=600`。

## 使用條件與特殊玩法

- 僅樂透彩系三個彩種；過關母項及各關皆不套差分。差分按使用者、彩種、玩法設定，無盤口維度。
- 平台關閉時整間公司差分視為0，設定值保留。代理有效授權需自身與所有代理祖先持有；判定每列是否生效看受益者（直屬上級），不是只看被設定者。Agent1列受益者為公司，豁免代理授權檢查；公司自身不可設差分列。
- 撤銷某代理授權（須先通過檔首的直屬下級檢查）後，以該代理為受益者的差分列（其直屬下級與直屬會員的列）休眠，設定值保留；恢復授權後重新生效。設定頁仍顯示原值並標示「目前未生效」，不代表投注已生效。
- **誰能設定**：上級可對自己管轄範圍內任一層代理檢視或寫入差分，不限直屬下線（例：公司可直接設aaa333）；但受益者恆為被設定者的直屬上級（設aaa333 → aaa222賺），與「誰能寫」無關（2026-09-29 新文件）。
- **生肖／尾數／五行**：選中副標籤選項（例：特肖／生肖「马」、尾數「0尾」、五行「土」，以設定頁副標籤為準）時整注成交在副層，用副差分與副下限 `sub_min_odds ?? min_odds`；其餘選項用主差分與主下限。注單明細 API 的 `frozenMainOddsGap`／`frozenSubOddsGap` 呈現為未用主欄0、未用副欄NULL（稽核工具依此判定，2026-09-24 主副擇一回歸凍結24／24符合）。
- **連肖／連尾：先扣再比**（2026-09-29 Aaron指定以桌面 `odds-gap (1).md` §3.4／§4.3 與 `chain-zodiac-tail-priced-odds.md` §3.3 為準，取代先前口述爭議及舊文件解讀）：
  1. 一般成員使用主差分與主下限；例外成員使用副差分與副下限（`sub_min_odds ?? min_odds`），副差分未設視為0。例外成員須依彩種及適用期別確認，不固定寫死生肖。
