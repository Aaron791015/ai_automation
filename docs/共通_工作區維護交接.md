## 5. 工具與規範的現況（值得知道的）

- **本機 Python 已升級為 3.11.9**（2026-08-26，per-user 安裝，不需系統管理員權限，安裝於
  `C:\Users\<使用者>\AppData\Local\Programs\Python\Python311`，PATH 已排在舊版 3.9 前面）。
  `scripts\setup_test_env.ps1` 要求的 `>= 3.11` 已滿足，`.venv` 已建好並通過 `requirements.txt` 全部套件安裝
  （含 Playwright Chromium、allure CLI）。
  - ⚠️ **舊的 Python 3.9 仍留著沒移除**（`C:\Users\<使用者>\AppData\Local\Programs\Python\Python39`），
    純粹因為新增 3.11 已解決版本需求，未特別清理舊版；共存不影響使用。
  - ⚠️ **當下啟動的終端機／Claude Code session 可能還看不到新 PATH**（Windows 環境變數只在新行程建立時讀取，
    不會即時推播給已經在跑的行程）——遇到 `python --version` 仍顯示 3.9 時，屬正常現象，
    重開一個新的終端機視窗即可看到 3.11；若在同一個舊 session 裡臨時需要，
    可在呼叫時明確把新路徑塞進 `$env:PATH` 前面（見 `新綜合_驗證交接.md` T9 的執行紀錄找範例）。
- **PowerShell 5.1（本機版本）讀取無 BOM 的 UTF-8 `.ps1` 檔會用系統內碼（本機是 cp950）誤判編碼**，
  含中文的腳本（`setup_test_env.ps1`、`run_ui_tests.ps1` 等）用 `-File` 直接執行會整份解析失敗。
  繞法：先建一份**加上 UTF-8 BOM 的暫存副本**（放在同一個 `scripts\` 目錄下，確保 `$PSScriptRoot` 算得對）
  再用 `-File` 執行，跑完即刪除暫存副本；或用 `PYTHONUTF8=1` 環境變數解掉連帶的 pip/requirements.txt 中文亂碼問題
  （這條專治 `pip install -r requirements.txt` 因為檔案裡有中文註解而 `UnicodeDecodeError` 的情況）。
