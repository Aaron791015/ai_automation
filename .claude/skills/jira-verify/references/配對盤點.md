## 8. 本地 Bug 單 ↔ JIRA 配對

本地 `reported` 欄位是重驗時查對應的唯一鍵，斷了就找不到驗證依據。

### 模式 A：使用者指定配對（**預設路徑**）

使用者開完 JIRA 單後會直接指定對應關係，如「本地 CRUX-019 對到 CRUX-905」。
**這是最準確的方式，有指定就不要再猜。**

```powershell
python scripts\jira_match_bugs.py --product CRUX --apply --only-pairs ^
    --pair CRUX-019=CRUX-905 --pair CRUX-017=CRUX-903
python scripts\gen_bug_index.py                    # 回填後必跑
```

`--only-pairs` 確保只回填指定的配對、不動自動判定結果。若該本地單 `reported` 已有值需覆寫，加 `--force`。

### 模式 B：全量盤點（存量補配對，使用者交辦時才做）

```powershell
python scripts\jira_match_bugs.py --product CRUX          # 初篩，不改檔
```

1. 跑初篩取得候選。
2. **Claude 必須逐條判讀，不得直接採信分數。** 字串比對在本專案的實測命中率很差，已知失效模式：
   | 失效原因 | 實例 |
   | --- | --- |
   | 繁簡混用 | 本地「万分之」↔ JIRA「萬分之」→ CRUX-012 ↔ CRUX-871 完全配不上 |
   | 措辭全異 | 「上繳貨量重複計入一次」↔「上繳貨量會虛增」（CRUX-010 ↔ CRUX-872） |
   | 同義詞 | 「前台退單不留日誌」↔「前台退碼未紀錄日誌」（CRUX-017 ↔ CRUX-903） |
   | 換角度描述 | 「多記幻影變更」↔「變更後值為 0」（CRUX-015 ↔ CRUX-896） |
   | 相近但不同 | 「月報表 GROUP BY 例外」vs「前台 API 洩漏例外堆疊」→ **不可配** |
3. 因此**必看「未達高信心者的候選（前 3 名）」區塊**，正解常在第 2、3 名；必要時另以
   `--jql 'project=X AND text ~ "關鍵詞"'` 針對性搜尋（CRUX-871/872 即是這樣找到的）。
4. **不要加 `--mine`**：實測有本地單對應到同事開立的 JIRA 單（本地 CRUX-011 ↔ CRUX-835）。
5. 產出四分類表交使用者確認：**確定配對** ／ **需裁定** ／ **本地有・JIRA 無（待開立）** ／ **JIRA 有・本地無**。
6. 經確認後才 `--apply --only-pairs`，並重跑 `gen_bug_index.py`。

### 模式 C：狀態矛盾檢查（產生待重驗清單）

```powershell
python scripts\jira_match_bugs.py --product CRUX --recheck
```

讀已回填的 JIRA 單號、查其現況，導出三類矛盾：

| 矛盾 | 意義 | 動作 |
| --- | --- | --- |
| 本地 `open` ↔ JIRA `Done` | RD 已修但我方未重驗 | **🔁 待重驗** |
| 本地 `rejected` ↔ JIRA 未結案 | 我方查證非缺陷，RD 卻還在修 | ↩️ 建議去 JIRA 撤單 |
| 本地 `fixed` ↔ JIRA 未結案 | 我方已重驗通過但單還開著 | 📌 可請 RD 關單 |

> **待重驗清單一律用這個指令即時導出，不要手寫成靜態待辦。**
> 靜態清單會隨 JIRA 狀態變動而失準；`--recheck` 每次都查現況，不會過期。

### 規則

- **一對多**（多張本地單指到同一 JIRA 單）：通常是 `superseded`／`rejected` 的舊單，
  **只回填現行有效的那張**，其餘留空並在報告說明。
- 不得因標題相近就自動認定同一問題；有疑慮一律列入「需裁定」。
- `--apply` 前一律經使用者確認；腳本預設不覆寫已填值（要覆寫需 `--force`）。


## 附錄：常用 JQL（批次盤點待驗清單）

```powershell
python tools\jira_qa\jira_api.py --jql "project = BOT AND status = Resolved AND updated >= -14d" --max 30
python tools\jira_qa\jira_api.py --jql "key in (BOT-799, BOT-801)"
python tools\jira_qa\jira_api.py --jql "project = BOT AND reporter = currentUser() ORDER BY updated DESC"
```

> 批次盤點只用來**列出候選**；實際驗哪幾張仍由使用者指定（第 0 節分工）。
