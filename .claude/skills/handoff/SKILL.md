# 開工與收尾 checklist

> **本 skill 只管「順序與清單」。** 內容怎麼寫見 `writeback`（分流表、交接檔骨架、四條紀律）。
>
> 為什麼需要它：收尾規則散在 CLAUDE.md、`writeback`、各產品 skill 共 8 處，
> 而 `lint_docs` 的 **D6（交接檔過期）** 就是專門在抓「收尾漏做」——
> 它的存在本身證明這件事經常被漏。

---

## 0. 先確認：我在哪一條線？

**七份交接活文件，先找到自己那一份**（⚠️ 產品線與效能線**互不重疊**，別寫錯）：

| 產品／線 | 交接活文件 |
| --- | --- |
| CRUX 功能／需求／回歸 | `docs/CRUX/CRUX_功能驗證交接.md` |
| CRUX 效能壓測 | `docs/CRUX/CRUX_Performance_效能驗證交接.md` |
| 七星 功能 | `docs/七星/七星_驗證交接.md` |
| 七星 效能壓測 | `docs/七星/七星_Performance_效能驗證交接.md` |
| 投注機器人 功能 | `docs/投注機器人/wbot_驗證交接.md` |
| 投注機器人 效能壓測 | `docs/投注機器人/wbot_Performance_效能驗證交接.md` |
| ★ **工作區維護（跨產品）** | **`docs/共通_工作區維護交接.md`** —— 規範、腳本、skill、測試框架的待辦 |

**判準**：這件事換一個產品還會不會存在？**會 → 共通檔；不會 → 產品檔。**

> ⚠️ 七星 ↔ wbot 是綁定的一組，但**交接檔各留一份**；跨兩側的事**兩邊各留一行指標**。

## 1. 開工 checklist

> ⭐ **只有 A 是無條件必做**（讀交接檔的兩節）。B 依任務觸發、C 綁在該做的那一刻。
> **開場把全部做完，多數任務有一半是白做的。**
> （2026-08-22 由「六步平舖」改為三層 —— 判準是「**這一步不先做，會不會造成不可逆傷害**」。）

### A. 開場必做 —— 不論任務是什麼，讀交接檔這兩節

| 讀哪一節 | 為了回答 |
| --- | --- |
| **`§1 當前 blocker`** | **這件事現在做不做得了** —— 卡住的事、卡在誰身上。有 blocker 時先確認它還在不在 |
| **`§5 測試資料現況`** | **哪些東西不能動** —— 見下方 ⛔ |

#### ⛔ 別把「刻意保留的 Bug 環境」當殘留清掉

`§5 測試資料現況`裡標明「刻意保留、屬哪一張單」的資料**不能還原** ——
那批資料就是該單的重現環境，清掉之後 RD 照著 Reproduce Steps 走會看不到現象。

**保留到該單 `status` 轉為 `fixed`／`rejected`／`superseded` 為止**（見 `bug-report` 的 Bug 環境保留節）。

> ### ★ 為什麼只有這一條不能「需要時再讀」
> B 的每一項都有明確的觸發訊號 —— 「我要重驗 JIRA」才需要待重驗清單。
> 但這一條的觸發時機是「**我看到一批看起來像殘留的資料**」，
> 而那一刻你的判斷是「這是垃圾，清掉」，**不會有任何訊號提醒你先去查交接檔**。
>
> **按需讀取的前提是「知道自己要查什麼」，這一條剛好不成立** —— 所以它必須前置。
> 而它的代價也是唯一不可逆的：清掉之後單子不可重現，要重新建資料才拍得到佐證。

### B. 依任務觸發（需要時再跑，不必開場全做）

| 這次要做什麼 | 跑什麼／讀什麼 |
| --- | --- |
| **不知道這條線現在該做什麼** | 讀交接檔 `§2 待辦總覽`（2.1 可立即動手｜2.2 等外部裁定｜2.3 等他人｜2.4 被 blocker 擋住） |
| **批量重驗 JIRA** | `python scripts\jira_match_bugs.py --product <產品> --recheck` |
| **規劃該驗什麼、還剩多少** | `python scripts\coverage_matrix.py --file docs\<產品>\<...>_驗證項目清單.md`（方法論見 `testcase-design`） |
| **接手一條不熟的線** | `python scripts\gen_bug_index.py <產品>` → `bugs/_view/01_待開立.md` 與待補回歸清單<br>（這三類積壓都不在交接檔的待辦表裡） |

⚠️ `jira_match_bugs` **要用的前一刻才跑，不要開場先導出** —— 靜態清單會隨 JIRA 狀態變動而失準。
開場導出、兩小時後才動手，中間 RD 關掉的單你看不到。
> 這句「一律即時導出」本來就寫在這裡，卻又被放進開工清單 —— **位置自相矛盾，2026-08-22 修正**。

### C. 綁定時點（不在開場，在該做的那一刻）

| 什麼時候 | 做什麼 |
| --- | --- |
| **第一次登入站台前** | 確認本 session 用哪一組子帳號 —— 站台是「**同帳號他處登入即踢掉前者**」。<br>分配慣例見 `config/environments.md`，完整規則見 **`browser-ops` §0** |

> **為什麼不放開場**：互踢是**登入的那一刻**發生的。
> 開場確認完、半小時後才開瀏覽器，中間別的 session 可能已經佔走。

## 2. 收尾 checklist

> ⛔ **知識回寫完 ≠ 交接完。** 兩件事都要做。

### ① 這批有跑測試 → 先判斷「能不能發」（沒跑測試就跳過）

```powershell
python scripts\analyze_run.py            # 讀 reports/allure-results，自動比對全部產品的 Bug 單
```

把失敗分成**真失敗／前置未備／環境問題**三類，並標出哪些已有對應 Bug 單 ——
allure 只告訴你「幾條紅」，發版判斷要的是「**新壞的**有幾條」。

### ② 知識回寫 → 載入 `writeback`

分流表（這則知識寫哪一份）、回寫完成的四個必做、更正他人條目的程序 —— 全在那裡。

### ③ 狀態交接 → 更新自己那份交接檔

| 這次產生的東西 | 去哪 |
| --- | --- |
| 做完的項目 | §2 劃掉（`~~T1~~ ✅ <日期> 完成，見 <報告路徑>`）並寫一行結果 |
| 等 PM／SA 裁定的規格問題 | §2.2 —— **這類別處沒有家**（不是缺陷、不是 side effect、不是知識） |
| 本次沒驗完的範圍 | §2.1 或 §2.4 |
| 卡住整條線的事 | §1 |
| 動過的測試資料（含已還原者） | §5 |
| 本批的 side effect 待驗項 | 批次交接檔 ＋ §3 加一列索引 |
| 缺陷 | 本地 Bug 單即可，**交接檔不重複列**（`_view/` 自動生成） |
| **新開的單，`regression` 欄填了嗎** | 沒填就補，或標明「為何補不了」的理由 |
| 最後 | **檔頭日期改成你的編輯日** |

⚠️ 編號（T／D／B）**寫入前當下重查**，多 session 併行沒有機制擋重複：

```powershell
python scripts\next_todo_id.py --handover <交接檔> --kind T
```

### ④ 跑 lint

```powershell
python scripts\lint_docs.py --product <產品>
```

| 代號 | 意義 | 怎麼處理 |
| --- | --- | --- |
| **D1／D5** | 斷連結 | **必修** |
| **D6** | 交接檔過期 | **收尾漏做的訊號**，見 §3 |
| **D7** | 規格行被刪改 | **停下來回答「這次有沒有人說要改？」** 有 → 寫明依據；**沒有 → 你正在把缺陷改寫成規格，去開單** |
| **D8／D11** | skill 章節指標斷掉／範本白名單漏分類 | **必修**（D11 見下） |
| **D13** | 乾淨範本鏡像落後原版 | 跑 `export_template.py --out <鏡像> --sync`，再到鏡像 commit／push。⚠️ **只在原版工作區出現**（見下） |
| D3／D4 | 描述失真／檔案偏大 | 技術債清單，不阻塞 |
| **W10** | Bug 單缺佐證截圖（`lint_bug_assets`） | 補圖；真的沒畫面就在 frontmatter 寫 `no_shot: <理由>`。⚠️ 只查 2026-08-26 之後開的單 |

> **D13 是什麼**：對外發送的是**鏡像**不是這個工作區，而「原版改了而鏡像沒跟上」
> **沒有任何機制會發現** —— 同事拿到的是舊的，而你以為已經給出去了。
> ⭐ 它**只在原版工作區**出現：根目錄有 `.template-export` ＝ 你手上就是範本，整項跳過；
> 沒設 `.template-mirror`（一行路徑、不版控）也跳過 —— 同事本來就沒有鏡像。
> ⚠️ 只有動到**會被匯出**的路徑才報；只改 `docs/<產品>/` 不會吵你。
>
> **D11 是什麼**：`export_template.py` 的白名單沒涵蓋到某個路徑。
> 漏分類的**通用檔會無聲地不再匯出**（同事拿到的範本少一塊），
> 漏分類的**產品檔會被夾帶出去**。跑 `python scripts\export_template.py --audit` 看細節。

### ⑤ 要 commit → 載入 `commit` skill

⛔ **取得許可前不得 `git add`／`git stash`**。

### ⑥ 收工

- MCP 瀏覽器 `browser_close`
- 測試資料依 CLAUDE.md §5 還原（**但據以開單的資料保留不還原**，並在 §5 登記）

## 3. D6 被觸發時怎麼修

D6 比對的是「**你負責的路徑有 commit，交接檔卻沒動**」。

| 做法 | 結果 |
| --- | --- |
| ⛔ 只把檔頭日期改成今天 | **等於把警告關掉，問題原封不動留給下一個人** |
| ✅ 回去補 §2 的待辦狀態、§5 的資料現況，**然後**才改日期 | 正確 |

> ⚠️ 「改檔頭日期」指的是**你自己回寫完**把它改成你的編輯日。
> 這與 `commit` skill 配套⑥「不要**替對方**改檔頭日期」不衝突 —— **主體不同**。
