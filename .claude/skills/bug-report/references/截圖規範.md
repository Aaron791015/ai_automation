# 截圖規範（框選、標注、蓋章、命名）

> 📝 本檔由 `bug-report` SKILL.md §3 移出（2026-08-22 拆層）。
> **真的要截圖時才需要讀**，所以不放在 SKILL.md 裡佔開場載入。
> Bug 單的欄位與回報格式見 `bug-report` skill。

### ★ 預設每張單都要有圖（2026-08-26 起）

> ⭐ 使用者裁示：「佐證截圖可以更快速的讓看的人了解問題點…**在圖中描述問題與顯示數值**，
> 看的人更能快速理解」。lint 的 **W10** 會查（只查 2026-08-26 之後開的單）。
>
> | 情況 | 怎麼做 |
> | --- | --- |
> | 有畫面 | **拍**，並符合下面的三要件 |
> | ⛔ `surface: 前台`／訊息・提示・顯示・版面 | **非拍不可** —— 這類用文字描述永遠不如一張圖 |
> | 真的沒畫面（API 回應、DB 對帳、壓測數據） | frontmatter 寫 `no_shot: <理由>` |
>
> ⚠️ **「要有圖」與「不能只有圖」不衝突** —— 內文的 Actual／Expect 數值由 **W4** 強制
> （`bugs/` 不版控，**圖丟了要讀得懂**；2026-08-25 兩天內弄丟過兩批共 15 張）。
> 圖是讓人快十倍看懂的那一層，數值是圖不在時的兜底。**兩層都要。**

### ★ 截圖規範：一張圖要能自己說明問題

> ⛔ **不得只丟一張原始畫面。** 讀者（RD／PM／半年後的你）不會知道要看哪個數字。
> 每張 bug 截圖都必須具備下列三件，缺一不可：

| # | 要件 | 說明 |
| --- | --- | --- |
| 1 | **框選問題點** | 紅框圈出出錯的欄位／數值／元素。多個重點就編號 ①②③ |
| 2 | **說明問題是什麼** | 每個框要有一句話：**實際值 vs 應為值**（附依據）。不是「這裡有問題」而是「實際 +550.24，應為 −129.76（＝20 − 20×7.488）」 |
| 3 | **一句話標題** | 圖頂說明條寫這張圖在講什麼（通常就是 Bug 標題） |

**同時框「錯的」與「對的」** —— 只框錯值，讀者無從判斷基準；把可對照的正確欄位一起框起來
（例：貨量 ¥20 正確、最大損失才是錯的），問題立刻自明。

#### 怎麼做：標注在瀏覽器裡完成，零成本

`tools/qa_common/shot.py` 會疊上紅框＋編號徽章，說明收進**頁尾圖例**、標題放**頁首說明條**。

> ⚠️ **說明文字絕不浮在畫面上。** 早期版本把標籤貼在框旁邊，結果直接蓋住它要說明的
> 那個數值 —— 比沒標注更糟。現在原地只放框與編號，文字一律進圖例（正常文檔流，不可能重疊）。

> ⭐ **截圖前先確認瀏覽器是全螢幕**（使用者 2026-08-20 裁示，作法見 `browser-ops` §0）。MCP 預設視窗只有 **929×925**，報表類的寬表格會被擠壓，**佐證圖上讀不到要對照的欄位**。<br>⛔ **`browser_resize` 不夠** —— 它只改 viewport，headed 的 OS 視窗不會動。

**Playwright MCP（探索／重現時）**：用 `browser_evaluate` 注入 `ANNOTATE_JS`，
`browser_take_screenshot` 後再注入 `CLEAR_JS`。兩段 JS 與 pytest 共用同一份原始碼，行為不會漂移。

```
browser_evaluate  function=() => { window.__annotate = <ANNOTATE_JS 內容>; }   ← 先裝 helper
browser_evaluate  function=() => window.__annotate({marks:[{selector:"…",
                            label:"實際 X，應為 Y（依據）"}], note:"CRUX-0nn 一句話標題"})
browser_take_screenshot  filename=".playwright-mcp/CRUX-0nn_01_說明.png"
browser_evaluate  function=<CLEAR_JS 內容>
```

⚠️ **`browser_evaluate` 沒辦法傳自訂 payload**（`element`/`target` 是給元素用的），
所以要先把 `ANNOTATE_JS` 裝成 `window.__annotate` 再呼叫 —— 直接傳 `{marks, note}` 會靜默變成
`undefined`，**回報「成功」但一個框都沒畫**。詳見 `browser-ops` 的 [`references/轉場觀察工具.md`](../../browser-ops/references/轉場觀察工具.md)。

> ⚠️ **`ANNOTATE_JS` 現在是 `async` 函式**（2026-08-20 起）——
> `window.__annotate({...})` 回傳的是 Promise，MCP 呼叫時要寫成
> `async () => await window.__annotate({...})`，否則拿不到回傳值（框仍會畫，但你看不到檢查結果）。

#### ⛔ 截完要看 `__annotate` 的回傳值，三個欄位都要是空的

它回 `{marked, missing, drift, overlays}` —— **`missing`／`overlays` 非空、或 `drift` 明顯大於 0，
那張圖就不能用**：

| 欄位 | 非空代表 | 怎麼修 |
| --- | --- | --- |
| `missing` | selector 對不到元素 → **那一處根本沒畫框** | 修 selector 重來 |
| `overlays` | 畫面上有**展開中的下拉／彈窗**（`.el-select-dropdown`／`.el-overlay`…） | 先 `Escape` 或點空白處關掉再截 |
| `drift` | 版面在標注過程中位移了（工具已自動校正，數值大代表這頁不穩） | 值 > 2 就重截一次確認 |

★ **這兩件事各害過一次，都是「圖看起來標好了、其實沒有」**（2026-08-20 六張圖重拍）：

- **框整體偏移**：頁首說明條把內容往下推，而座標在推移前就量好了 → 紅框整齊地框在空白處；
  說明條愈多行偏得愈多（2 行約 30px、4 行約 50px），小樣本不一定看得出來。
  **已在 `ANNOTATE_JS` 修掉**（插入說明條後等版面重排、畫完再自我校正一次），
  回歸案例 `tests/tooling/test_shot_annotate.py::test_說明條造成的版面推移必須被校正`。
- **下拉沒關**：Element Plus 的 `el-select` 點完選項**不會自動關閉**，
  展開的面板正好蓋住表格中段 —— 而那裡往往就是要框的欄位。
  `capture_annotated(strict=True)` 現在會直接讓案例失敗。

#### ⛔ MCP 截完必須再蓋一次「已標注」標記

`lint_bug_assets` 的 W7 檢查的是 PNG 裡的 **tEXt 標記**，不是看畫面有沒有紅框。
pytest 走 `capture_annotated()` 會自動 `stamp_png`，**MCP 這條路沒有任何一步會蓋**——
圖明明標好了卻被判「未標注」。用這支腳本搬移＋蓋章，不要手抄 Python：

```powershell
python scripts\stamp_shots.py --product CRUX .playwright-mcp\CRUX-0nn_01_說明.png
# 需要改名：來源=目標檔名
python scripts\stamp_shots.py --product CRUX ".playwright-mcp\probe.png=CRUX-0nn_02_說明.png"
```

它會一併擋掉**檔名不合規**與**覆蓋既有圖**（要覆蓋加 `--force`），`--dry-run` 可先試跑。

> ⛔ **拍完就立刻搬，不要等一批拍完再一起搬** —— `.playwright-mcp/` 的內容**會在 session 中途消失**（2026-08-20 實際遺失 3 張，整段 UI 操作重做）。細節與正確節奏見 `browser-ops` §8。
⚠️ 只蓋標記、**不會幫你畫框** —— 蓋在沒標注的圖上等於騙過 lint，別這樣用。

**pytest（自動化案例）**：

```python
from qa_common.shot import capture_annotated

capture_annotated(page, "reports/shots/CRUX-050_01_大類卡最大損失.png",
                  marks=[{"selector": "…", "label": "實際 +550.24，應為 −129.76"}],
                  note="CRUX-050 虛盤组六多码大類卡最大損失錯值")
```

- **selector 對不到會直接讓案例失敗**（`strict=True`）—— 寧可失敗，也不要產出一張沒標到問題點的圖。
- 截圖後**自動清除標注**；手動注入時務必記得 `CLEAR_JS`，否則後續畫面都帶紅框。

#### 例外：非瀏覽器來源的圖

DB 查詢結果、桌面截圖等無法用上述工具標注者，**在 Bug 單內文補一張對照表**
（欄位／實際值／應為值／依據）緊接在圖後，以文字標注取代視覺標注。**不得只有圖。**

### 截圖的檔案規範（由 lint 強制，不是靠記）

| 規則 | 說明 |
| --- | --- |
| 命名 | `<ID>_<序2碼>_<說明>.png`；修復驗證圖 `<ID>_fixed_<序2碼>_<說明>.png` |
| **純他人單（無本地 ID）** | **加 `JIRA-` 前綴**：`JIRA-CRUX-882_fixed_01_….png`。JIRA 與本地都用 `CRUX-nnn`，不加前綴會撞命名空間 |
| 引用要寫**完整路徑** | `![說明](shots/CRUX-029_01_….png)`。**不可用縮寫**（如 `shots/CRUX-043_05/08`）—— 點不開，且 lint 會誤判成死圖 |
| 共用圖 | 以**首位擁有者 ID** 命名，其他單引用同一路徑、不複製 |
| 非 bug 佐證的探索截圖 | 放 `docs/<專案>/探索截圖/`，**不得混入 `shots/`** |
| `_fixed_` 圖上傳 JIRA 不回貼 | 自動豁免死圖檢查；整單豁免可加 frontmatter `shots_external: true` |
