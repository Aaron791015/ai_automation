# 回寫分流：知識與狀態該寫哪裡

> **本 skill 是全工作區的權威分流表。** 其他 skill 一律指回這裡，不各自複述。
>
> 📝 2026-08-22 從 `browser-ops` §7／§7.1 抽出 —— 它與瀏覽器無關，卻被 6 支 skill 引用，
> 導致「想查知識該寫哪」必須載入一支瀏覽器操作手冊。

**兩件事要分開，缺一不可**：

| | 處理什麼 | 去哪 |
| --- | --- | --- |
| **§1～§3 知識回寫** | 這東西怎麼運作、怎麼操作、有什麼坑 | 機制文件／程序文件／memory |
| **§4 狀態交接** | 這件事做完了／換誰卡住了／哪份資料被動過／還有什麼沒驗完 | 交接活文件 |

> ⛔ **知識回寫完 ≠ 交接完。**「等 PM 裁定」「還沒驗完的範圍」不會出現在任何機制文件裡；
> 不寫進交接檔，下一個 session 只能從報告內文考古。

## 1. 分流表：這則知識寫到哪

**落筆前先問：這是「畫面長怎樣」還是「這東西怎麼運作／怎麼操作」？**

| 知識性質 | 寫到哪 | 例 |
| --- | --- | --- |
| **UI 元素**：selector、頁面路徑、DOM 結構、可靠輸入法、欄位型態 | `docs/<產品>/UI元素對照_*.md` | 「某欄位只認逐字輸入，`fill` 不進 model」 |
| **API 契約**：端點、參數、回應結構 | 同上（該檔的 API 契約節） | 「查明細必須帶某個旗標，不帶會漏資料」 |
| **操作程序**：多步驟流程、前置條件、不可逆操作、還原 SOP | 產品的**程序文件** | 「封盤後怎麼還原」 |
| **功能機制**：語義、公式、生效規則、生命週期、優先序 | 產品的**機制文件** | 「某個差值的基準是設定當下的值」 |
| **核心演算法**：金流／計算的規則 | `docs/<產品>/<產品>_領域知識摘要.md` | 加權平均公式 |
| **零散踩坑、時序陷阱** | **memory**（含 **Why** 與 **How to apply**） | 「不改某欄位會被踢回登入頁，易誤判為 token 過期」 |
| **缺陷** | `docs/<產品>/bugs/`（見 `bug-report`） | — |
| **★ 狀態**：待辦、blocker、等外部裁定、動過的測試資料 | 產品的**交接檔**（§4） | 「某站台停用中，某單定案卡住」 |

> 本 skill 所稱 **memory** 僅指已有明確授權路徑的可審查共享 Markdown（可在本 repo 或 `$HOME/Aaron-Agent` 等已授權共享路徑，仍受目前檔案系統權限約束）；不得寫入或改寫 Claude／Codex 原生 session、credentials、auth 或 memory store。找不到可審查的授權路徑時，保留在本次專案文件或回報中，不以原生 memory 代替。

### ★ 三條邊界判準（分不清時用這個，不要憑感覺）

| # | 問 | 答案決定去向 |
| --- | --- | --- |
| **①** | **這則知識會不會演進？** | 會（公式、規格、數值、狀態）→ **`docs/`**；相對穩定（反直覺的坑、協作偏好）→ memory |
| **②** | **需不需要在「我還不知道要查什麼」的時候浮現？** | 要 → **memory**（索引常駐）；等我要用時去查就好 → `docs/` |
| **③** | **這是知識還是狀態？** | 狀態（做完了／卡住了／動過了）→ **交接檔**（§4） |

> ⭐ **判準①的理由**：`docs/` 失效時 lint、其他 session、git diff 都會抓到；
> **未經索引與驗證的記憶容易持續帶入過時資訊**；共享 Markdown 仍應可審查，不能假設載入 context 的內容永遠有效。
> **所以會演進的東西一律不進 memory。**
>
> 實證（2026-08-22 稽核）：漂移的 memory **全都是裝了公式／規格本體的那幾則**；
> 只裝「指標＋Why＋踩坑」的**全部沒有過期**。

### memory 的三個條件（要同時成立）

1. 跨 session 還會用到
2. 從程式碼與既有文件看不出來
3. ⭐ **需要在「還不知道要查什麼」時就浮現**

⚠️ **memory 引用章節時用標題，不要用編號** —— 編號會漂，而 memory 這層沒有 lint 會抓到失效指標。
〔✅「見 CLAUDE.md 的版本控制章節」／❌「見 CLAUDE.md §8.2」〕

## 2. 現有文件放不下時才開新檔

新檔要做到三件事：

1. **檔名說得出內容**〔✅ `<產品>_後台操作程序.md`／❌ `<產品>_雜記.md`〕
2. 檔頭寫清楚**本檔職責邊界**與「相關文件」指標
3. 開頭放一張**快速索引**（「我要做什麼 → 看哪一節」）

> ⛔ **不要把所有東西都倒進 `UI元素對照_*.md`。**
> 教訓：該檔曾長成 609 行、混了六類主題，「期數還原 SOP」埋在「UI 元素對照」這個檔名下，
> 其他 session 依意圖搜尋完全找不到，**等於沒寫**。

## 3. 回寫完成的四個必做（依實際異動觸發）

以下同步只在本次實作／驗證任務確實新增／變更知識、文件範圍或狀態時觸發。純唯讀查詢、文件審閱一律只回報結果（即使發現新問題），除非使用者另行授權落檔，不建立回寫、索引或交接檔變更。

1. **新增文件、移動內容或改變既有檔案職責／範圍時才登記或修正 `docs/INDEX.md`** —— 描述必須**涵蓋該檔實際內容**，不可只加不改。
2. **新增可檢索知識、文件或意圖範圍時才更新產品 skill 的意圖對照**，以「**使用者會怎麼問**」為鍵（「還原封盤期數」而非「開獎號碼頁」）。
   ⚠️ 一列最多兩行，只回答「去哪裡看」＋「一句話的坑」；**知識本體留在機制文件**。只修正同一範圍內的既有內容時，不為湊列而重複新增。
3. **原位置留指標** —— 只有把內容從既有檔移走時，原處才留一行「**已移出 → 見 `<新檔>`」**。
4. **狀態類的另外更新交接檔**（§4）—— 僅在待辦、blocker、外部裁定、測試資料或其他目前狀態確實改變時更新；知識回寫完不等於交接完。

## 4. 產品交接檔（活文件）：狀態的唯一去處

每個產品／線**一份**、常駐、隨進度更新。

只有本次實作／驗證任務確實改變待辦、blocker、外部裁定、測試資料或其他目前狀態時才回寫交接檔；純唯讀查詢／審閱即使發現問題也只回報，不因使用本 skill 而新增交接檔寫入，除非使用者另行授權落檔。

**檔名**必須以 **`驗證交接.md`**（產品線）或 **`維護交接.md`**（跨產品）結尾 ——
這不只是慣例，`lint_docs` 的 **D6** 靠它辨識活文件；取別的名字＝不會被檢查到。
⚠️ 放在 `docs/` 直下的跨產品交接檔**還要**加進 `lint_docs.py` 的 `COMMON_HANDOVERS`。
**檔頭第一段要有** `> **最後更新：YYYY-MM-DD**`，D6 靠它判斷有沒有跟上進度。

### 骨架（節次順序刻意固定，接手者才能盲讀）

```
§1 ⛔ 當前 blocker        卡住的事／卡在誰身上／影響到什麼（沒有時留「目前無 blocker」，勿刪節）
§2 ★ 待辦總覽             2.1 可立即動手｜2.2 等外部裁定｜2.3 等他人處理｜2.4 被 blocker 擋住
§3 批次交接索引           一次性交接檔哪一份還有殘留（不逐項複製）
§4 文件地圖               知識在哪（指向機制文件與產品 skill）
§5 測試資料現況           動過且未還原、或還原了但值得知道的
§6 維護規則               開工讀什麼、收尾寫什麼
```

新增一份時，除骨架外還要在兩處各補一列：**CLAUDE.md 的交接檔清單**、
**`scripts/lint_docs.py` 的 `HANDOVER_SCOPE`**（它負責哪些路徑；不補則退回 `docs/<產品>`）。

### 四條紀律

1. **只放狀態，不放知識。** 機制／公式／selector 一律留在機制文件，本檔只在 §4 指路。
2. **不重複權威來源。** 逐張 bug 的狀態由 `bugs/_view/` 自動生成，交接檔只放摘要與**導出指令**
   （手寫清單必然過期）。
3. **收尾就要更新** —— 做完的劃掉並寫結果，新產生的依上表歸位，**最後改檔頭日期為你的編輯日**。
   漏了會被 `lint_docs` 的 **D6** 抓到；⚠️ **只改日期不改內容等於把警告關掉**。
4. **共用檔紀律**：比照 CLAUDE.md 的共用檔章節「只動自己的條目」，只改自己那幾列、別重寫整節；
   要劃掉別人列的項目前**先確認確實做完了**。

> ⚠️ **編號（T／D／B）在寫入前「當下」重查**，多 session 併行時沒有機制擋重複：
> ```powershell
> python scripts\next_todo_id.py --handover <交接檔> --kind T
> ```
> 撞號時改號的是**後寫入者**，並一併改掉報告與批次交接檔裡的引用。

### 為什麼要「一次性交接檔 ＋ 活文件」兩層

批次交接（`bugs/_handover/交接_…_<日期>.md`）是某次任務的快照，任務結束就凍結 ——
好處是可追溯、壞處是**會愈積愈多且沒人知道哪份還活著**（曾累積 5 份，其中 4 份從未復查）。
活文件負責**把還活著的那些收攏成一張表**。

## 5. ★ 更正他人已寫的條目

**通則是「只動自己的條目」**，但有一個例外：

> **他人條目所陳述的「事實」被你這次的驗證推翻時，要就地更正或與你的新列合併，
> 不可另起一列放著不管。**

**為什麼要破例**：意圖對照表、INDEX 描述、機制文件是拿來**被查**的。留下「舊列說 A、新列說 B」的
並存狀態，下一個 session 只會讀到其中一列，**而且先讀到哪一列純屬運氣** —— 等於你把一顆錯誤答案
留在索引裡。這比動到別人的字嚴重得多。

### 界線很窄，別擴大解釋

| | |
| --- | --- |
| ✅ 可改 | **可驗證的事實值**（日期、公式、狀態、檔案路徑、API 欄位名），且你手上有**這次實測／裁定的佐證** |
| ⛔ 不可改 | 措辭、排版、分類方式、你覺得寫得不好的地方 |
| ⛔ **不可改** | **帶裁定來源的「規格」陳述**（「使用者／PM ×× 裁定」「as-designed」「這是規格，不是缺陷」）。<br>**實測與規格不符時那是缺陷，要開單，不是改文件** —— 除非你手上有**新的變更聲明**。判準見 CLAUDE.md「實測與文件不符時」 |

### 程序：兩條必做 ＋ 一條分流

**必做①**：**寫明新值與依據**（含日期，如「2026-08-14 由 X 放寬並統一至各報表」）。
**必做②**：在**回報中主動點名**你動了誰的條目 —— 不要等對方自己發現。
**分流③**：**原陳述要不要留，看這份文件拿來做什麼**：

| 文件性質 | 例 | 原陳述 | 為什麼 |
| --- | --- | --- | --- |
| **狀態型** | 交接檔的 T／D／B 列 | **保留**（刪除線或「原記：…」） | 它本身就是**歷史紀錄**，接手者需要看到「原本以為 A、後來查出 B」 |
| **索引型** | `docs/INDEX.md`、skill 意圖對照表、機制文件 | **直接取代，不保留** | 這類是拿來**被查**的，留著舊值等於在索引裡留一顆錯誤答案 |

### ⭐ 改值前後各跑一次 trace（2026-08-22 新增）

```powershell
python scripts\trace_value.py --value "<舊值>"
```

**改任何規格值之前先跑一次**（看看它散在哪些檔）、**改完再跑一次**。
完成條件是「現行有效陳述不再存在矛盾的舊值」；歷史快照、Bug 重現紀錄、變更日誌或引用中的舊值若有清楚標註其歷史性，可以合法保留，不為了讓搜尋結果歸零而刪除。

> **為什麼需要這一步**：2026-08-22 的稽核找到四處矛盾，成因**全都是「更新時只加不刪」** ——
> CLAUDE.md 的 co-commit 範圍、利潤率檔的三種說法、INDEX 同一格前後矛盾、日誌類型 4 類 vs 5 類。
> 上面的分流③ 早就寫著「索引型要直接取代」，但**沒有任何機制在執行時提醒**。

## 6. 回寫完就跑一次

```powershell
python scripts\lint_docs.py --product <產品>
```

本次有實際回寫時才跑受影響產品／路徑的 lint；純唯讀查詢／審閱不因本 skill 強制跑 lint。**各代號的意義與處理方式見 `handoff` skill §2④**（那裡是收尾流程的權威，本節不重複列）。修復本次變更造成或阻擋交付的錯誤；無關既存問題如實列出，不擴大整修範圍。
只提醒一句：**D7 先由 agent 查證既有變更依據**；有依據就引用，沒有依據不得用實測覆蓋規格，僅暫停受影響修改並回報／開單，繼續獨立工作。查證不等於取得新的使用者批准。

完整收尾流程（含狀態交接、commit）見 **`handoff` skill**。
