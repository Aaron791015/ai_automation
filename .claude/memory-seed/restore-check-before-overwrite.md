> 📌 **範本內建的通用教訓。** 文中的「產品A／產品B／產品C」是範本原型留下的匿名實例，
> 只是為了讓教訓有具體場景 —— **教訓照用，例子換成你自己的產品**。

測試會**整批覆寫**既有資料的功能（如 產品A 水賠間距保存＝重建整張對照表）時，
在動手前先對**全部**候選對象跑一次「可還原性檢查」：把存量參數丟回現行的驗證規則，
看它是否還通過。不通過的對象一律**跳過不測**，並在報告列為 🚫 無法驗證＋原因。

**Why**：存量資料常是**舊規則**下建立的，新版驗證可能拒絕它。此時保存一次就回不去了——
「先記錄基準值再還原」這套標準做法會在還原那一步失敗。
實例（2026-08-11，JIRA A-622 重驗）：某玩法 110 個玩法中，组三／组六的水賠表間距
0.04／0.02 不是玩法基準間距 0.4／0.2 的倍數，若當時照原計畫測下去就會永久破壞回水基礎資料。

**How to apply**：
1. 先用唯讀 API 抓**全量**基準快照（不是只抓要測的那幾個），存 scratchpad。
2. 對每個對象套用現行驗證規則，算出「可還原 / 不可還原」清單。
3. 測試選樣優先挑**冪等**對象——存量參數已等於預設值者，保存等於原樣重建，淨變更為零。
4. 收工前把全量快照**逐筆比對**一次，證明淨變更為零，而不是只檢查動過的那幾筆。
5. 「資料沒變」不等於「保存成功」。要另找獨立佐證（產品A 可查 `水赔置换` 日誌筆數，
   成功才留痕、被驗證擋下不留痕）。
