# 測試案例須讓一般 QA 可獨立執行

- 記錄日期：2026-09-02
- 適用範圍：所有手動與自動化測試案例文件

Aaron 要求測試案例不能只讓原作者或自動化工程師看得懂。一般 QA 不詢問原作者，也應能依文件完成操作、判定結果並還原資料。

每條案例至少要明確寫出：

1. 案例名稱：包含測試對象、操作情境與預期結果。
2. 測試範圍：彩種、玩法、子項與選項；未全覆蓋時直接列出缺口。
3. 前置條件：頁面、開關狀態、必要資料，以及是否需開盤或跨系統。
4. 測試資料：固定輸入值、目標列與控制組，不能只寫「新值」「某選項」「一段時間」。
5. 步驟：逐步寫清楚按鈕、輸入值、保存或重新整理時機，以及最後還原方法。
6. 判準：每一步可觀察的期望值；未知規格或疑似缺陷不可直接當成 PASS oracle。
7. 案例邊界：名稱不可宣稱驗到實際未驗的後端、排程、金流或時序行為。

文件中的固定測試值必須與 pytest 實際使用值一致；修改腳本測試值時要同步案例清單、docstring 與 Allure 說明，不能為了文案易讀而另造一組數字。
