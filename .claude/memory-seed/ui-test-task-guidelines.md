> 只是為了讓教訓有具體場景 —— **教訓照用，例子換成你自己的產品**。

與使用者確立的 UI 測試任務協作方式（2026-07-22）：

任務描述四要素：**目標**（產品＋前/後台＋頁面路徑）、**情境**（操作步驟粗描述）、**預期**（明確驗收條件）、**寫入許可**（write_action 授權範圍）。模板與檢查規則已寫入 `.claude/skills/ui-test/SKILL.md` 階段 0。

實務原則：

1. **一次一個功能區塊**：任務橫跨多區塊時主動提出拆分方案，讓測試檔與 commit 乾淨。
2. **點名被測行為**：涉及 API 加速時先確認案例的被測行為，據此套用 [[api-vs-ui-rule]]（被測行為一律走 UI）。
3. **先探索後實作**：UI 不明時可拆兩步——先探索並更新 UI 對照文件、提出案例清單，經使用者確認後再實作。
4. **環境、帳密、避重命名不需使用者在任務中重述**：以 `config/` 與 skill 現行設定為準。

**Why:** 新 session 沒有先前對話上下文，四要素讓任務可直接執行；拆小與先探索降低返工。

**How to apply:** 收到 UI 測試任務時先跑 SKILL.md 階段 0 檢查；缺「目標/預期」先反問，缺「情境」可先探索提案。
